Executive Function Assessment Platform

A multi-step digital assessment experience designed to collect responses, calculate executive function scores and support the automated creation of personalised reports.

01 / Context

Turning a detailed assessment process into a clearer digital journey.

The project required a structured online assessment that could guide users through a large set of questions without making the experience feel overwhelming.

Beyond collecting answers, the system needed to process the responses, calculate results across different executive function areas and support the delivery of personalised reporting.

My work covered the front-end assessment experience, interaction design, scoring logic and the connections between the form and the wider automated workflow.

03 / Development decisions

Designing the logic around the user journey.

The project involved more than displaying questions. The interface, scoring model and automated workflow had to work together without making the assessment unnecessarily difficult for the person completing it.

01

Interaction design

Breaking a long assessment into manageable steps.

Presenting the full assessment at once would create a long, demanding form. I structured the experience across multiple steps so users could focus on a smaller amount of information at a time while still moving through one connected assessment.

Considerations

Progress / required responses / navigation / cognitive load

02

Scoring logic

Converting individual responses into executive function scores.

Individual questions contribute to different executive function areas, so the scoring logic needed to group the relevant responses correctly and calculate results for each area rather than treating the assessment as one overall score.

Considerations

Question mapping / domain calculations / consistent output

03

Integration

Connecting the browser experience to the reporting workflow.

The assessment could not end when the user pressed submit. Response data and calculated results needed to leave the front-end in a predictable structure so the wider automation could process them and support personalised reporting.

Considerations

Structured data / webhook transfer / automation / reporting

04 / Scoring architecture

Turning individual answers into structured domain results.

The assessment uses grouped question mappings so individual responses can be processed into separate executive function domain scores.

/ simplified logic

One scoring function, multiple domains.

The scoring structure uses a shared calculation with domain-specific question mappings rather than duplicating calculation logic for each executive function area.

This makes the logic easier to maintain and reduces duplication when results need to be processed consistently.

Input
Numeric assessment responses
Mapping
Questions grouped by domain
Calculation
Average score for each group
Output
Structured domain result object
scoring-example.js JavaScript 
const domainMap = {
  workingMemory: ["q01", "q04", "q07"],
  taskInitiation: ["q02", "q05"],
  flexibility: ["q03", "q06"]
};

// Shared calculation keeps scoring logic consistent across domains.
function average(values) {
  const validValues = values.filter(Number.isFinite);

  // Return a predictable value if no valid responses are available.
  if (validValues.length === 0) {
    return null;
  }

  const total = validValues.reduce(
    (sum, value) => sum + value,
    0
  );

  return total / validValues.length;
}

function calculateDomainScores(responses) {
  const scores = {};

  for (const [domain, questions] of Object.entries(domainMap)) {
    const values = questions.map(
      question => responses[question]
    );

    scores[domain] = average(values);
  }

  return scores;
}

06 / Interface & UX

Making a detailed assessment easier to move through.

The interface needed to support a substantial amount of information without presenting the assessment as one long form. The experience was structured around clear stages, progress and focused questions.

01

A multi-step assessment journey.

Breaking the assessment into stages reduces the amount of information competing for attention at one time and gives users a clearer sense of where they are in the process.

Focus
Progress / Navigation / Cognitive load
Role
Front-end development / UX

02

Keeping users informed while their report is generated.

After the final assessment step, the interface provides a clear processing state while the personalised report is being generated. Progress feedback helps users understand that the workflow is still active rather than leaving them on an uncertain loading screen.

Focus
Progress feedback / Processing state / Reassurance
Technology
HTML / CSS / JavaScript

07 / Personalised reporting

Completing the journey with a usable result.

The final stage turns the completed assessment into a clear output for the user rather than ending the experience at submission.

/ final state

From processing to report ready.

Once the reporting workflow has completed, the interface updates to confirm that the personalised report is ready and gives the user a clear action to access it.

The transition from questionnaire completion, through processing, to a finished result was designed as part of one continuous user journey.

08 / Technical takeaways

What this project reinforced about building connected systems.

Building the assessment meant thinking beyond individual screens. The user interface, scoring logic, data structure and automated workflow all depended on each other behaving predictably.

01

Keep interface logic and scoring structure clear.

Separating the assessment journey from the domain mapping and scoring calculations makes the application easier to understand, test and maintain as the assessment changes.

02

Predictable data makes integrations easier.

When information needs to move between the browser and an automation workflow, consistent field structures and outputs reduce ambiguity between each stage of the system.

03

Processing states are part of the user experience.

A technically successful workflow can still feel broken if the user does not know what is happening. Progress and completion feedback became an important part of connecting the assessment interface to the reporting process.
